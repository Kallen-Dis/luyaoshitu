# 报告设计

[返回 README](../README.md) · [算法设计](algorithm-design.md) · [共享标注](shared-markings.md)

报告把一次分析组织成“范围、设施、居民可达性、成因与建议”，数字来自已生成结果，不额外调用大模型生成事实。本文说明数据口径与阅读方式；界面章节按数据是否存在显示，不依赖固定编号。

## 1. 数据契约：先确定正式范围

一次结果是 GeoJSON Feature：`geometry` 保存正式生活圈，`properties` 保存采样、设施、网格、报告及质量信息。

| 数据 | 主要字段或来源 | 用途 |
| --- | --- | --- |
| 正式几何与面积 | `geometry`、`area_km2`、`geometry_method` | 地图主范围、面积评分和统计范围 |
| 原射线参考 | 融合结果保留的射线几何、面积与统计 | 方法对照，不能冒充当前主结果 |
| 设施 | `coverage` | 圈内 / 周边数量、设施点及检索状态 |
| 网格 | `blindspots`、`scope_method` | 居民点的缺失、未知、细分及统计口径 |
| 评分与诊疗 | `report` | 总分、维度、盲区比例、灰色区域和处方 |
| 融合质量 | `fusion` 或 `fusion_review`、回退原因 | 采用状态、证据、核验及方法对照 |
| 辅助证据 | `gridcheck`、等待、围挡、标注与 warnings | 解释结果及数据限制 |

采用融合后，应更新正式几何、面积、圈内设施、网格纳入范围、盲区占比、灰色区域、相应评分与导出。发布在副本中完成全部重建后才替换原结果；失败则保留原射线整份结果。

**方向均衡、路径效率仍来自射线与路线采样。** 这不是把融合范围重新抽射线测一遍。过街等待前后面积也属于其原校正实验口径，不应将它们误标成最终融合面积。

样例和历史保留生成时版本，不因当前代码变化自动得到新采样；显示“历史回看不新增调用”不代表“当初计算没有消耗”。

实现：[main.py](../backend/app/main.py)、[fusion.py](../backend/app/isochrone/fusion.py)、[resultView.ts](../frontend/src/lib/resultView.ts)。

## 2. 页面阅读结构

报告以综合结论和评分总览为入口，再按需要展开细节：

| 内容 | 回答的问题 |
| --- | --- |
| 综合结论 | 整体怎样、主要问题是什么、建议做什么、有什么数据限制 |
| 五维评分与雷达图 | 哪一方面相对薄弱，哪些维度未完成测量 |
| 灰色区域 | 服务盲区集中在哪里，缺少哪类设施 |
| 自动诊疗 | 优先打通还是补设，建议影响多大 |
| 降级与数据时效 | 哪些查询失败、判定未知或数据较旧 |
| 过街等待与施工围挡 | 路线模型延误、已知围挡如何影响结果 |
| 生活圈校正与方法对照 | 当前采用融合还是射线，差异和核验等级如何 |
| 网格交叉校核 | 超时采样、绕行线索、存疑点及辅助估计 |
| 设施覆盖与逐类最近设施 | 圈内有多少、附近哪些设施可作为出行候选 |
| AI 二次核对、标注对照、历史与导出 | 如何补漏、复核并带走结果 |

详细章节使用标题右侧的独立展开 / 收起控件；灰色区域、方法对照、交叉校核和逐类最近设施当前默认收起。报告栏本身也可收起给地图让出空间，按钮需可通过键盘操作并表明状态。

实现：[ReportCard.tsx](../frontend/src/components/ReportCard.tsx)、[ReportSection.tsx](../frontend/src/components/ReportSection.tsx)、[App.tsx](../frontend/src/App.tsx)。

## 3. 五维评分的数学口径

评分以理想方格路网作路网参照，避免拿不可实现的直线圆作为所有真实社区的满分标准。记目标秒数为 $\tau$、参考速度为 $v$，步行默认 $v=1.2$ 米 / 秒，$r=v\tau$。

方格路网的曼哈顿球是菱形，面积为 $2r^2$；最短方向半径与最长之比为 $1/\sqrt2$；均匀方向的平均绕行为：

$$
\frac{1}{2\pi}\int_0^{2\pi}(|\cos\theta|+|\sin\theta|)\,d\theta=\frac4\pi.
$$

定义 $\operatorname{clip}(x)=\min(100,\max(0,x))$：

| 维度 | 计算 | 权重 |
| --- | --- | --- |
| 路网可达 | $S_A=\operatorname{clip}(100A/(2r^2))$，面积统一单位 | 30% |
| 方向均衡 | $S_C=\operatorname{clip}(100(r_{min}/r_{max})/(1/\sqrt2))$ | 20% |
| 路径效率 | $S_D=\operatorname{clip}(100(2.25-\bar d)/(2.25-4/\pi))$ | 15% |
| 设施覆盖 | 已覆盖品类权重占有效品类总权重的百分比 | 20% |
| 可达均衡 | $S_E=100(1-\operatorname{mean}(b_c))$，$b_c$ 为有效关键品类盲区比例 | 15% |

$A$ 为正式范围面积，$\bar d$ 为方向采样的平均绕行系数。路径效率在 $4/\pi$ 及以下封顶，在 2.25 及以上为零；它是项目定义的诊断分，不是官方规划评级标准。

设施覆盖的类别权重分别是：生鲜 1.4、医药 1.3、小学 1.3、基础医疗 1.1、养老 1.0、文体 0.9。该维度看“类别是否存在”，不以门店越多分数无限增加；居民是否都到得了由网格均衡维度表达。

缺失维度不按零分填充，总分对实际参与的权重重新归一：

$$
S=\frac{\sum_{k\in K}w_k S_k}{\sum_{k\in K}w_k}.
$$

等级阈值为：85 分及以上“优”，70–85“良”，55–70“中”，低于 55“弱”。展示时应同时看到未测维度，不能把只算路网的高分与全维度分数无条件等同。

直线圆面积 $\pi r^2$ 只用于解释直线估计可能高估多少，不作为路网可达维度的分母。十五分钟步行的方格参照面积约 2.33 平方公里，直线圆约 3.66 平方公里。

实现：[score.py](../backend/app/report/score.py)。

## 4. 设施覆盖、未知与最近设施

六类设施的“圈内数”按正式几何统计；“附近数”按检索范围统计。检索失败写查询失败，不能显示成已确认零家。

买菜待确认门店单列，不计已知覆盖；如果当前只收录到待确认门店，生鲜覆盖维度按不确定处理。服务盲区主要对生鲜、医药、小学逐格实测，其他类别不冒充已经完成同样深度的网格检测。

每类盲区比例用缺失面积权重除以已判定面积权重，未知不入分母，判定覆盖不足时不评分。细分子格按 0.25 个百米格计数，因此 15.75 格是面积折算，不是有小数个人。

“逐类最近设施”卡片目前先按直线选择最近候选，再以平均绕行与延误估计参考分钟：

$$
\widehat t=\frac{d_{straight}\,\bar d}{v_0}
+\frac{d_{straight}\,\bar d}{1000}D_{km}.
$$

它不是居民出行模块已经验证的真实步行最近一家，界面应标“估算”。点“怎么走”才进入独立出行测距与路线流程，可能新增调用。

## 5. 灰色区域与成因

将圈内缺至少一类设施的网格按上下左右相邻合并，面积排序编号 A、B、C……，较小区域可不单独编号。子格与继承格通过统一派生网格参与，避免父子重复统计。

逐“格 × 品类”分析：

- **路网阻隔**：直线附近存在候选，但已知步行距离超过阈值。建议核查通道、入口或过街条件。
- **供给缺口**：附近没有相应候选。建议补设或扩大服务供给。
- **未知**：证据不完整，不能强行归因。

区域可能同时包含多种成因。绕行不证明一定是铁路或河流，容量不足等现场问题也不由距离算法直接证明。

灰色表示设施服务盲区；红色斜线表示生活圈采样中确认超时的证据；绿色表示正式范围。三者不是同一种“可达 / 不可达”分类。

实现：[regions.py](../backend/app/report/regions.py)。

## 6. 自动处方、选址与模拟

### 自动处方

从已有测量推导建议，不新增 API 调用。路网阻隔按对应设施及需求聚合，提出“打通”；供给缺口以最大覆盖贪心提出“补设”，每类最多两处。默认设置最小改善面积门槛，网格变细时同步换算格数，不能因拆成小格就更容易触发处方。

估算效果依赖典型绕行系数，必须显示“估算”。未建设的新道路无法由现有地图验证，不能称为已实测打通后的效果。

### 核验选址

对前几个分散备选点，在既有路网上模拟居民点到拟建位置的步行距离，按实测消去盲区的面积重排，并可逆地理编码为可读地址。默认最多三个备选、点对预算 400；不足时剩余候选标未核验，不将未测项当零收益。

### 规划模拟

新建设施只影响对应品类候选与网格覆盖，重新生成评分和报告；围挡模拟则需要重新检查相应路线与范围。模拟结果是方案副本，原始正式体检保留。

“实测选址”只证明现有道路下到该位置的测距情况，不证明土地可建设、设施建成后会开放或服务能力足够。继承子格模拟按父格来源合并测量，避免重复花四倍点对。

实现：[prescribe.py](../backend/app/report/prescribe.py)、[siteplan.py](../backend/app/report/siteplan.py)、[simulate.py](../backend/app/report/simulate.py)。

## 7. 综合结论与 AI 二次核对

综合结论先从结果提取事实，再按“总体结论、主要问题、诊疗建议、数据边界”四段模板生成。同一份结果得到相同文字，不调用外部大模型，不额外产生配额。未知、回退与降级应出现在数据边界说明中。

AI 二次核对是另一条可选流程：通过百度 Agent Plan 在灰色区域附近寻找疑似漏收设施，用户可按补录模拟或提交共享标注。AI 返回的是线索，不自动替换正式盲区、评分或统计。

实现：[narrate.py](../backend/app/narrate.py)、[crosscheck.py](../backend/app/poi/crosscheck.py)。

## 8. 导出与复现

| 格式 | 用途 |
| --- | --- |
| Markdown | 综合结论、评分、设施、网格、诊疗及证据说明 |
| CSV | 网格与品类判定明细，用于表格复核 |
| GeoJSON | 正式生活圈及其属性，支持 GIS 检查 |
| JSON | 完整属性数据 |
| ZIP | 报告与数据打包 |
| PDF | 前端使用浏览器打印，版面由打印样式控制 |

导出读取已有快照和报告，不重算路线。CSV 保留父格记录及已生成的子格行，并标明格边长、圈外状态和实测品类；做面积汇总时须用子格替代对应父格，不能直接对全部行求和。CSV 对可能被表格软件解释为公式的单元格转义；文件名做安全处理。导出结构与页面字段覆盖不必逐项完全相同，但核心数值和正式范围必须一致。PDF 也不等于后端额外生成了一份新分析。

复现至少保留中心与坐标系、时间阈值、正式方法、算法版本、采样来源、生成时间、采用标注版本、未知 / 降级、预算与独立核验说明。缓存可能过期，真实地图会变化，因此“重算相同地点”不保证长期得到完全相同数值。

实现：[export.py](../backend/app/export.py)、[NarrativeCard.tsx](../frontend/src/components/NarrativeCard.tsx)、[App.tsx](../frontend/src/App.tsx)。

## 9. 验收要求

1. 融合采用 / 拒绝两条分支，地图、面积、设施、网格、评分及导出一致；辅助候选不参与正式统计。
2. 未测维度不算零，查询失败不算没有，未知格不当盲区。
3. 父子格不重复计数；孔洞与多片区域正确排除；地图裁剪与中心取样统计的差别有说明。
4. 雷达图、总分、等级和导出公式一致；方向 / 路径指标的来源明确。
5. 处方估算、路网核验、模拟副本和正式结果有清楚标识。
6. 综合结论不新增事实；标注影响可追溯到采用版本。
7. 窄屏、展开 / 收起、地图联动与打印 PDF 实际检查，避免隐藏内容遮挡或数字截断。

评分与叙述回归见 [评分测试](../backend/tests/test_score.py)、[结论测试](../backend/tests/test_narrate.py)；实际融合质量还需按 [算法验收](algorithm-design.md#8-采用回退与独立验收) 提供对应地点的独立报告，不能用页面显示正常代替效果验收。
