# 路遥识途——基于百度地图的生活圈智能规划

> 路虽遥，可识途。计算**真实路网**上的步行等时圈，统计圈内民生设施覆盖情况，
> 输出可视化体检报告并自动标注服务盲区。

## 为什么需要真实路网

国家推行"15 分钟便民生活圈"，要求居民步行 15 分钟内可获得基础医疗、教育、购物、养老等服务。
但现有评估多用"以中心点画圆"的直线缓冲区，而道路并非直线——红绿灯、铁路、河道、
施工围挡都会大幅压缩实际可达范围。

本项目在上海市普陀区的实测数据说明了差距有多大：

| 样例社区 | 真实路网可达面积 | 直线画圆面积 | 真实/直线 | 平均绕行系数 |
| --- | --- | --- | --- | --- |
| 曹杨新村街道 | 1.757 km² | 3.66 km² | 48% | 1.31 |
| 桃浦镇 | 1.304 km² | 3.66 km² | **36%** | **2.15** |

但面积只是起点。真正影响结论的是**设施可达性**，而这里的偏差要大得多：

| 样例社区 | 直线圆内设施 | 等时圈内设施 | 直线法漏判的居民点 |
| --- | --- | --- | --- |
| 曹杨新村街道 | 70 处 | 41 处 | 基础教育 **19.2%** 判错 |
| 桃浦镇 | 11 处 | **0 处** | 基础教育 **100%** 判错 |

桃浦镇的两种口径给出的不是"精确度差异"，而是完全相反的结论：
一个说配套尚可，一个说六个品类在真实可达范围内全部缺失。
面积口径的偏差是均匀的，可达性的偏差却集中在被铁路、河道切开的局部——
恰恰是最需要被看见的地方。这也是本项目要逐网格判定、而非只报一个总分的原因。

完整对比见 [`reports/straight-line-comparison.md`](reports/straight-line-comparison.md)，
由 `scripts/compare_straight_line.py` 依据快照与本地缓存离线生成，零 API 消耗。

## 技术方案

百度地图不提供等时圈接口，也不开放底层路网数据。本项目用**扇形采样 + 射线插值**
在仅有"批量算路"这一原语的条件下逼近真实可达边界：

1. 以中心点为原点，按方位角均匀发射 N 条射线（默认 36 条）；
2. 每条射线上按半径梯度布置候选点（默认 200~1400 米共 7 档）；
3. 全部候选点一次性提交批量算路，取回真实路网步行耗时；
4. 在每条射线上找到耗时**首次**超过阈值的区间，线性插值反解边界半径；
5. 环形平滑各方向半径，连成多边形。

三个关键取舍：

- **首次穿越而非最远可达**。某方向 600 米处超时、900 米处却达标（绕行到了另一条通道），
  边界仍取 600 米。等时圈描述连通可达区域，跨越不可达地带的"飞地"不应计入。
- **失败点视为障碍而非跳过**。算路返回不可达时射线在此截断。当作缺失值忽略会让等时圈
  越过河道、铁路等真实屏障，得出偏乐观的结论。
- **查询失败绝不退化为 0**。POI 检索失败一律用 `None` 表达，网格测距全部失败时判为
  "未知"而非"盲区"。把"查不到"当成"真的没有"，会让 API 故障伪装成服务盲区——
  对一个核心输出就是"这里缺设施"的系统，这是最危险的错误。界面上"查询失败"与
  "缺失"是两种不同的显示，未判定的网格也不计入盲区占比。

## 从「圈内有没有」到「谁走不到」

只统计圈内设施数量，回答不了"哪一片居民走不到"——圈内有两家药店的社区，
被铁路切开的另一侧照样是盲区。故在等时圈内按 150 米布网格，逐点判定：

1. 中心点到各网格做一次批量算路，得到真实步行耗时，即**热力图**的强度；
2. 对菜市场、药店、小学三类命题点名的设施，逐网格判定真实路网 1 公里内能否走到；
3. 走不到的网格标为该品类的**盲区点位**。

第 2 步是配额消耗的大头，三条措施把它压到约原来的四分之一到十分之一，
且都不牺牲结论的严格性：

- **直线距离是步行距离的下界，据此免费剪枝**。直线就超过 1 公里的设施，步行必然超过。
  故某网格若连最近的设施直线距离都超标，无需任何请求即可判定为盲区。
  桃浦镇最近的菜市场直线 1091 米，这一整类因此零消耗。
- **够近就停**。判定"1 公里内有没有"只需找到一个达标设施，不必求真正的最近距离。
  每轮给未决网格各分配"第 k 近"的候选，多数网格第一轮就被最近的设施覆盖掉。
- **按候选分组装箱**。共用同一候选的网格并成一次请求，矩阵退化成一列，
  点对数等于网格数——这是最省配额的形状。

被河道隔开的近点会被算路如实排除，由更远的候选接管；某网格把直线阈值内的候选
全测完仍无一达标，才判为盲区，这是严格成立的。

普陀区两个样例的判定结果差异极大（百分比为该品类走不到的居民点占**已判定网格**之比，
测距失败的网格不计入分母）：

| 样例社区 | 网格数 | 盲区网格 | 菜市场不可达 | 药店不可达 | 小学不可达 |
| --- | --- | --- | --- | --- | --- |
| 曹杨新村街道 | 78 | 16 | 5.1% | 1.3% | 19.2% |
| 桃浦镇 | 56 | 56 | 92.9% | 82.1% | **100%** |

桃浦镇最触目的一点：**六个品类在真实 15 分钟等时圈内全部为零**，
而检索半径内明明有 7~12 处。最近的公园直线距离仅 677 米，
但等时圈半径只有 438~833 米且被严重切割——直线看得见，真实路网走不到。
这正是直线缓冲区评估会得出"配套齐全"结论的地方。

## POI 多源清洗

一个品类对应多个检索关键词（「菜市场」还要并查「农贸市场」「生鲜超市」），
提升召回的代价是同一设施被反复返回。清洗解决四类脏数据：

| 问题 | 处置 | 实测效果 |
| --- | --- | --- |
| 多源重复 | 归一化名称 + 50 米坐标量化去重 | 曹杨「医药」原始 56 条去重掉 28 条 |
| 误召回 | 按品类黑名单拦名称 | 「小学」召回的「小学生辅导中心」被剔除 |
| 坐标缺失或为 0 | 直接剔除 | — |
| 超出范围 | 以**落在等时圈内**为准，而非圆形半径 | — |

名称归一化会剥掉「（兰溪路店）」这类后缀，故必须叠加坐标，
否则同品牌的两家不同门店会被误并成一家。

详细的 API 能力边界实测、算法设计与配额策略见 [`reports/quota-report.md`](reports/quota-report.md)。

## 快速开始

### 环境要求

- Python 3.11+
- Node.js 18+
- 百度地图开放平台账号（[申请地址](https://lbsyun.baidu.com/apiconsole/key)）

### 申请两个 AK

本项目需要**两个** AK，分工不同，不能混用：

| 类型 | 用途 | 控制台配置 |
| --- | --- | --- |
| 服务端 AK | 后端调用 Web 服务 API（地理编码、地点检索、批量算路） | 建议配置 IP 白名单 |
| 浏览器端 AK | 前端加载 JS API GL 渲染地图 | Referer 白名单填 `localhost/*` 及正式域名 |

> Referer 白名单的格式是 `域名/*`，**不接受端口通配符**。写 `127.0.0.1:*` 会报格式错误，
> 应写 `127.0.0.1/*` 或 `localhost/*`，端口会被自动忽略。

### 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env` 填入两个 AK。该文件已被 `.gitignore` 排除，请勿提交。

```env
BAIDU_SERVER_AK=你的服务端AK
VITE_BAIDU_BROWSER_AK=你的浏览器端AK

# 以下参数为实测值，通常无需修改
BAIDU_MAX_QPS=8               # 实测地理编码 12 并发安全、16 触发限流
BAIDU_MATRIX_BATCH_SIZE=100   # 批量算路单次终点数硬上限
BAIDU_HTTP_TIMEOUT=30
BAIDU_MAX_RETRIES=3
BAIDU_RETRY_BACKOFF=0.5
```

### 启动后端

```bash
pip install -r backend/requirements.txt
cd backend && python -m uvicorn app.main:app --reload --port 8000
```

接口文档：http://127.0.0.1:8000/docs

### 启动前端

```bash
cd frontend && npm install && npm run dev
```

访问 http://localhost:5173

前端通过 Vite 代理访问后端，浏览器端 AK 由后端 `/api/config` 运行时下发，
不编译进静态产物——换 Key 无需重新构建。

### 一键 Docker 演示

本机已安装 Docker 时：

```bash
cp .env.example .env   # 填入两个 AK
docker compose up --build
```

浏览器打开 http://localhost:8080 。首屏读取 `data/samples/` 预生成快照，不消耗地点检索配额。

## 配额约束（重要）

地点检索（`place/v2/search`）的免费日配额实测仅约 150~160 次，
经申请后已提升至 **3000 次/日**。但**批量算路的日配额并未一同提升**，
它现在成了最紧的约束。

关键在于它的计量口径：**批量算路的日配额按「点对数」计量，不按请求数**。
实测同一天发出约 140 次请求、共 2479 个点对即触发 `302`，
而同日的地点检索只用掉 38 次。所以省配额要盯的是点对数——
单次请求的硬约束是**起点数 × 终点数 ≤ 100**（不是终点数 ≤ 100，
实测 100 起点 × 1 终点正常，101 个点对才报 `status: 2`），
多起点装箱能把请求数压低一个数量级，但一个点对也省不下来。

真正省点对的是「直线距离是步行距离的下界」这条剪枝，详见上一节。
两个样例的实测消耗（`scripts/check_coverage_offline.py` 离线估算，零消耗）：

| 样例社区 | 直线剪枝掉的网格 | 剪枝后点对数 | 朴素做法 |
| --- | --- | --- | --- |
| 桃浦镇 | 116 个 | 108~151（实测重跑实发 **60**） | 约 1400 |
| 曹杨新村街道 | 0 个 | 312~914 | 约 1950 |

桃浦镇的设施本就偏远，直线一剪几乎全部判定完毕；曹杨设施密集，
第一轮就被最近的设施覆盖掉，实际贴着下界走。

因此架构上：

- 应用默认读取 `data/samples/` 下的**预生成快照**，首屏零 API 消耗；
- 实时计算仅在用户显式触发时执行，且覆盖层与盲区层可单独关闭；
- 所有 POI 与算路结果按 50 米网格量化后落盘缓存，重复演示零消耗
  （算路缓存**按点对存储**，与计量口径一致，换一个候选集也能复用）；
- 矩阵请求**串行发出**：并发时一旦撞上限流或配额耗尽，多个分块会各自退避重试
  并互相踩踏，既烧配额又拿不到结果；
- 每次运行都打印实发点对数，`client.matrix_pairs` 是这个系统里最该盯的计数器。

错误码按三类分别处置，混用代价很大：

| 类别 | 状态码 | 处置 |
| --- | --- | --- |
| 瞬时噪声 | `401` `402`、网络异常 | 指数退避重试 3 次 |
| 配额耗尽 | `301` `302` | 立即终止，转快照或降级 |
| 配置错误 | `200` `210` `220` | 终止并告警 |

> 对 `302` 重试是配额上的自杀行为：配额越接近耗尽，302 出现越频繁，
> 每次失败又被放大成四次请求，形成正反馈急剧加速消耗。这是实测踩过的坑。

> 反过来也踩过：排查"整块矩阵请求拿不到结果"时，我们先入为主地当成 `401` 并发限流，
> 照着这个结论调了半天限流参数，实际是 `302` 配额耗尽。两者的表象完全相同，
> 处置却相反——一个该退避重试，另一个必须立即停手。
> 教训是失败必须留痕：客户端把整块失败的形状与状态码记进 `matrix_failures`，
> 生成脚本直接打印，才让真正的原因一眼可见。

## 项目结构

```
backend/app/
  config.py              运行时配置，默认值取自实测结论
  baidu/
    client.py            异步客户端：连接池、令牌桶、重试、缓存
    errors.py            错误码三分类
    cache.py             坐标量化磁盘缓存
  isochrone/
    algorithm.py         扇形采样 + 射线插值
    geometry.py          球面几何、点在多边形内、网格布点
  poi/
    catalog.py           民生设施品类词表与误召回黑名单
    collect.py           多关键词采集与四类清洗
  report/
    score.py             体检评分（路网层 + 覆盖层 + 均衡层）
    blindspot.py         网格级盲区识别
  samples.py             预生成快照仓库
  main.py                FastAPI 入口
frontend/src/
  api.ts                 后端接口客户端
  baiduMap.ts            JS API GL 按需加载器
  components/            地图（热力网格 + 盲区）、指标面板、体检报告
scripts/
  probe_quota.py         API 能力边界探测
  probe_matrix_shape.py  批量算路的形状约束探测
  probe_network.py       网络链路诊断
  probe_endpoint.py      单接口精细探测
  pick_sample_area.py    两阶段样例社区选址
  run_isochrone.py       等时圈 + 覆盖 + 盲区的命令行入口，兼快照生成
  check_coverage_offline.py   离线核查圈内计数、估算配额消耗，零 API 消耗
  compare_straight_line.py    直线圆与等时圈的对比测试报告，零 API 消耗
  _singleton.py          单实例锁，防止重复启动烧光配额
data/samples/            预生成示例数据（仅派生结果，不含 POI 原始记录）
reports/                 实测分析报告
```
